# v0.0.1rc03 — Firefox Dock Robustness Pass

## Goal

Harden the already-working single Firefox HWND docking POC before adding multi-tile or file-management features.

## Changes from rc02

- Validate browser/host HWND lifetime with `IsWindow` before Win32 operations.
- Add periodic docked-window health checks.
- Clear stale dock state if Firefox is closed while embedded.
- Emit a recovery status instead of leaving Workspace in a false "docked" state.
- Make Workspace shutdown explicitly detach/restore Firefox before exit.
- Stop selecting an arbitrary existing Firefox window when launch isolation fails.
- Refuse **Dock Existing** when more than one Firefox top-level window is available.
- Avoid duplicate `MoveWindow` calls when host dimensions have not changed.
- Improve runtime evidence around candidates, PID/HWND, focus, detach and loss/recovery.

## Acceptance criteria

- Command-line Debug build passes.
- Existing rc02 launch/dock behavior remains functional.
- Resize, mouse, keyboard and scroll remain functional.
- Detach/re-dock can be repeated without leaving Firefox borderless or stranded.
- Closing Firefox while docked does not crash Workspace.
- A new Firefox can be launched/docked after a docked-window-loss recovery.
- Closing Workspace while Firefox is docked restores Firefox to a normal top-level window.
- Multiple existing Firefox windows do not cause an arbitrary window to be selected by **Dock Existing**.

## Out of scope

No 2x2 layout, File Manager, workspace persistence, routing, API integration or browser automation in this RC.
