# v0.0.2rc01 — 2×2 Multi-Tile Workspace POC

## Goal

Scale the validated single-Firefox HWND docking baseline into four independent browser tiles without introducing File Manager, routing or API automation yet.

## Architecture change

```text
MainWindow / Workspace
  |
  +-- BrowserTile 1 -- BrowserDockHost -- Firefox HWND A
  +-- BrowserTile 2 -- BrowserDockHost -- Firefox HWND B
  +-- BrowserTile 3 -- BrowserDockHost -- Firefox HWND C
  +-- BrowserTile 4 -- BrowserDockHost -- Firefox HWND D

Shared safeguards
  +-- Firefox launch serialization gate
  +-- Browser HWND ownership registry
  +-- 1-second multi-tile health monitor
```

Each `BrowserTile` owns its URL, controls, launch cancellation state, BrowserDockHost and tile-local status. `MainWindow` is responsible for layout, common health polling, aggregate status, Detach All and orderly shutdown.

## Multi-tile safeguards

### Launch serialization

Only one `Launch + Dock` operation may perform Firefox new-HWND discovery at a time. Other tile launches wait on a shared `SemaphoreSlim`. This avoids two near-simultaneous launches treating each other's new Firefox windows as candidates.

### HWND ownership

`BrowserDockRegistry` prevents the same HWND from being attached to two `BrowserDockHost` instances. Ownership is released when a window is detached, lost or a dock attempt rolls back.

### Existing-window selection

The rc03 safety rule remains: **Dock Existing** only proceeds when exactly one visible top-level Firefox window is available. Multiple candidates are not guessed.

## Acceptance criteria

- Command-line Debug build passes.
- Four browser tiles render in a 2×2 layout.
- Four separate Firefox windows can be docked simultaneously.
- Each tile can focus/detach independently.
- Splitter and main-window resizing keeps each HWND within its own tile.
- One docked Firefox closing does not affect other tiles or crash Workspace.
- Detach All restores all tracked Firefox windows.
- Workspace shutdown restores every surviving docked Firefox window.
- Near-simultaneous launch requests do not cross-assign newly created Firefox HWNDs.
- Runtime log identifies browser actions by tile.

## Out of scope

File Manager, file drag/drop, selectable 2×3/2×4 layouts, persistence, endpoint registry UI, context/message routing, AI APIs and browser automation are deferred.
