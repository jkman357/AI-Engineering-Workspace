# v0.0.2rc02 — Workspace-Owned Browser Shutdown

## Goal

When AI Engineering Workspace exits, close the Firefox windows that Workspace itself created through `Launch + Dock`, while leaving pre-existing Firefox windows safe.

## Ownership rule

```text
Launch + Dock
  -> isolate exact Firefox HWND + PID
  -> record Workspace ownership
  -> dock HWND into tile
  -> on Workspace exit: Detach -> validate HWND/PID/class -> WM_CLOSE

Dock Existing
  -> no Workspace launch ownership
  -> dock HWND into tile
  -> on Workspace exit: Detach/restore only
```

The ownership record survives a manual `Detach`. Therefore, a Firefox window launched by Workspace will still close at Workspace shutdown even if it was detached first.

## Safety rationale

Multiple Firefox top-level windows can share one Firefox process ID. The shutdown path must not use process-wide termination as its normal mechanism. rc02 sends `WM_CLOSE` only to recorded Workspace-created top-level HWNDs after checking:

- HWND still exists;
- current HWND PID equals the recorded PID;
- process name is still `firefox`;
- top-level window class is still `MozillaWindowClass`.

A mismatch is logged and the close is refused rather than risking closure of an unrelated window.

## Acceptance criteria

- Four `Launch + Dock` browser windows can be docked simultaneously.
- Closing Workspace closes all surviving Workspace-launched Firefox windows.
- An external `Dock Existing` Firefox window is restored and remains open when Workspace closes.
- A Workspace-launched window that was manually detached still closes when Workspace closes.
- A Firefox window already closed by the user does not cause shutdown failure.
- No Firefox `Process.Kill()` is used by this feature.
- Runtime log contains per-tile close ownership and `WM_CLOSE` outcome evidence.
