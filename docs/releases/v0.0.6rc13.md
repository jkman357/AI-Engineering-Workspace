# AI Engineering Workspace v0.0.6rc13

Status: **Release Candidate — active v0.0.6 line, not frozen**

## Purpose

rc13 fixes the multi-Browser keyboard focus-ownership regression observed in rc12. Docked Firefox keyboard input is known to be possible; the failure pattern is Browser-pane switching/ownership rather than a fundamental WPF HWND-hosting limitation.

## Focus model

rc12 maintained a persistent `AttachThreadInput` bridge for each dock. rc13 removes that lifetime ownership and introduces `FirefoxInputCoordinator`.

For explicit root-HWND recovery, the coordinator performs:

1. resolve Workspace and Firefox input thread IDs;
2. temporarily call `AttachThreadInput(..., true)` only when the threads differ;
3. call `SetFocus` on the reparented Firefox root HWND;
4. capture focus/foreground diagnostics;
5. in `finally`, immediately call `AttachThreadInput(..., false)` if this transaction attached it.

No Browser pane retains a persistent bridge. Normal mouse clicks are left to Firefox, which owns address-bar and web-content focus transitions. Normal Browser focus handling does not enumerate or guess internal Firefox child HWNDs.

`TabIntoCore` and the Focus toolbar button remain minimal root-HWND recovery paths; they are not acceptance prerequisites for ordinary typing.

## Manual multi-Browser PASS gate

The following must be tested on Windows with four real docked Firefox windows **without pressing Focus first**:

```text
B1 -> address bar -> type 111
B2 -> address bar -> type 222
B3 -> Google search -> type 333
B4 -> ChatGPT prompt -> type 444

B2 -> type aaa
B3 -> type bbb
B2 -> type ccc
```

All input must reach the currently clicked Browser pane. A pane that appears focused but routes keyboard input elsewhere is FAIL.

This source package includes static regression checks for the coordinator architecture and documents this real-machine acceptance gate. The interactive Firefox gate must still be executed on the target Windows workstation.

## Retained rc12 behavior

- explicit Create New / Cancel confirmation for a clean Workspace;
- Save / Discard / Cancel semantics for New Workspace with unsaved changes;
- deterministic default F1/F2 + B1-B4 reset;
- Auto Fit reset state;
- Browser startup at Google;
- `.aew` persistence boundaries;
- 64×64 endpoint badges and compact version UI;
- Windows Shell/TortoiseGit/7-Zip integration;
- asynchronous Git decorations;
- Firefox launch ownership cleanup;
- standard-user, API-free architecture;
- security/privacy wording and MIT License.
