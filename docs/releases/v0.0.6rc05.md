# AI Engineering Workspace v0.0.6rc05

Status: Release Candidate — **not frozen**

`v0.0.6rc05` continues the active `v0.0.6` RC line. It corrects two issues found during real-machine testing of `v0.0.6rc04`: Free Layout resize was limited to a small lower-right grip, and the focus bridge imported `GetCurrentThreadId` from the wrong Windows DLL.

## Changes

- replace the lower-right-only resize grip with true pane-border resize chrome;
- support left, right, top, bottom, and all four corner resize directions;
- show standard resize cursors (`SizeWE`, `SizeNS`, `SizeNWSE`, `SizeNESW`);
- keep a WPF-only resize band outside the inset Browser/File pane content so the foreign Firefox HWND does not consume all resize hit testing;
- resizing from the left/top adjusts pane position while preserving the opposite edge;
- enforce pane minimum width/height and prevent left/top resize from moving the pane to negative workspace coordinates;
- keep a docked Firefox HWND fitted to the Browser pane during live resize;
- remove the old visible lower-right `◢` resize grip;
- correct `GetCurrentThreadId` P/Invoke from `user32.dll` to `kernel32.dll`;
- retain `v0.0.6rc04` browser-focus diagnostics and compact icon toolbar behavior.

## Primary rc05 gates

1. Build with `build.cmd`.
2. Run with `run.cmd`.
3. Switch to Free Layout or begin a border resize from Auto Fit (which should enter Free Layout).
4. Resize both File and Browser panes from every edge and corner.
5. Confirm the mouse cursor changes appropriately at each resize edge/corner.
6. Confirm a docked Firefox window follows Browser pane resize continuously.
7. Launch + Dock Firefox and verify the previous `GetCurrentThreadId` entry-point failure no longer occurs.
8. Re-test keyboard input inside normal web-page text fields.

The `v0.0.6` line remains an RC until explicitly frozen.
