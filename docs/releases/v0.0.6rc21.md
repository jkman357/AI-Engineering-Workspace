# AI Engineering Workspace v0.0.6rc21

## Firefox Launch-Only Control

Status: release candidate / diagnostic control. The active v0.0.6 line remains unfrozen.

## Why rc21 exists

Real-machine rc20 testing still could not compose Chinese with Zhuyin even after Firefox was kept as an unmodified native top-level window with no `SetParent`, owner reassignment, or style mutation. rc20 still changed Firefox geometry with `SetWindowPos` and synchronized visibility with the Workspace. It also exposed a pseudo-dock Z-order limitation: when B2/B3 were launched, earlier independent top-level Firefox windows could be obscured by the WPF Workspace.

rc21 removes those remaining Workspace window-management variables and becomes the cleanest control in the rc12-rc21 investigation.

## rc21 launch-only rules

After a Browser endpoint launches Firefox and discovers the new HWND, the Workspace may **observe and track** that HWND, but must not mutate the Firefox window.

Firefox path requirements:

- `SetParentUsed=False`;
- `OwnerMutation=False`;
- `StyleMutation=False`;
- `GeometryMutation=False`;
- `VisibilityMutation=False`;
- no `SetWindowPos` against Firefox;
- no `SetWindowPlacement` against Firefox;
- no Workspace-driven `ShowWindow` against Firefox;
- no `AttachThreadInput`;
- no root `SetFocus`;
- no `SetForegroundWindow`;
- no `SendInput`;
- no input-language synchronization;
- no `ActivateKeyboardLayout`;
- no synthetic IME composition;
- no Firefox child-HWND enumeration/focus guessing.

The Browser pane remains a Workspace endpoint and launch/status placeholder. Firefox itself appears as a normal independent top-level Windows application window at the position/size chosen by Firefox/Windows. This is intentionally **not** the desired final dashboard UX.

The Workspace may still keep launch ownership metadata so a Firefox window launched by a Browser pane can be closed during pane/Workspace shutdown. That lifecycle bookkeeping does not alter the live window while the control experiment runs.

## Real-machine gate

Do not begin with B1-B8. Test **B1 only** first.

1. Start v0.0.6rc21.
2. Launch Firefox from B1.
3. Do not press the Workspace Focus button; rc21 suppresses focus mutation anyway.
4. Click Firefox directly.
5. Type `abc123`. English/number input must PASS.
6. Switch Windows input to Zhuyin.
7. Compose and commit `你好`.
8. Switch back to English and type `xyz789`.
9. Capture the runtime log.

Interpretation:

- **Chinese PASS:** one of rc20's remaining window-management actions (`SetWindowPos` / visibility management / geometry lifecycle) was materially involved. Reintroduce those variables one at a time.
- **Chinese FAIL:** Workspace-side Firefox window mutation/window management is effectively ruled out. Investigate the Firefox new-window/shared-process/shared-GUI-thread/TSF lifecycle and compare a Workspace-launched window with a manually-created Firefox window under the same process/profile.

## Known limitations

Because rc21 does not move or visually attach Firefox to Browser panes, it is a control build only. Multi-pane dashboard geometry, clipping, z-order, minimize/restore coupling, and Show IDs behavior are not Browser-hosting acceptance criteria for this RC.
