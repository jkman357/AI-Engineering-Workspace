# AI Engineering Workspace v0.0.6rc19

## Scope

Native top-level Firefox pseudo-dock prototype. This continues the active v0.0.6 RC line and is not a frozen release.

## Real-machine finding from rc18

rc18 removed persistent input bridges, automatic root focus, and input-language synchronization from normal Browser interaction. Real-machine testing then produced a clean boundary:

- English/number keyboard input works in the pseudo-hosted Browser workflow;
- Zhuyin/Chinese IME composition does not;
- the runtime log can still show the Firefox root as the foreground/GUI-active/GUI-focus window while the composition path is unavailable;
- therefore rc19 stops trying to repair the reparented `SetParent` model with additional focus or IME message manipulation.

The rc19 experiment changes the Browser hosting boundary rather than adding another keyboard-focus patch.

## rc19 architecture change

Firefox is no longer reparented into the WPF Browser pane.

```text
WPF Browser pane
    └─ native geometry-anchor HWND
           ↓ GetWindowRect (screen coordinates)

Firefox native top-level HWND
    ├─ remains top-level (WS_CHILD is not used)
    ├─ no SetParent
    ├─ Workspace is assigned only as the top-level owner
    └─ SetWindowPos mirrors the Browser pane rectangle
```

The owner relationship is not a child-parent relationship. Firefox remains a native top-level window so Windows/Firefox retain their normal keyboard, TSF, and IME activation path.

Implementation rules:

- `BrowserDockHost` remains a WPF `HwndHost`, but its HWND is only a geometry anchor.
- Do not call `SetParent` for Firefox in rc19.
- Keep Firefox top-level and remove only the visible caption/frame chrome while pseudo-docked.
- Bind the Firefox top-level owner to the Workspace top-level HWND with `GWL_HWNDPARENT`; restore the original owner on detach.
- Use the anchor's `GetWindowRect` and `SetWindowPos(... SWP_NOACTIVATE ...)` to mirror screen position and size.
- Synchronize pseudo-dock geometry after pane resize/layout, Workspace move, viewport resize, scrolling, Window activation, and Window restore.
- Hide pseudo-docked Firefox windows while the pane or Workspace is hidden/minimized; reshow and resynchronize them when visible again.
- Normal Firefox mouse/keyboard input is untouched. There is no `AttachThreadInput`, no `SetFocus`, no input-language synchronization, no IME synthesis, and no Firefox child-HWND focus guessing.
- The `⌖ Focus` recovery action now requests native top-level activation through `SetForegroundWindow`; it does not bridge input queues.
- Retain HKL / `GetGUIThreadInfo` / IME message diagnostics as observation only.

## Prototype limitations to validate

Top-level pseudo-docking deliberately trades true Win32 child clipping for native Firefox input ownership. rc19 therefore needs explicit validation for:

- scrolling and partial clipping in Free Layout;
- overlapping panes and z-order interaction with File panes;
- multi-monitor / mixed-DPI movement;
- Workspace minimize/restore and Alt-Tab behavior;
- external Firefox windows from the same process remaining unaffected.

These are rc19 prototype validation items, not claimed PASS results.

## Windows manual PASS gate

Do not press `⌖ Focus` during the normal-input portion of this gate.

1. Launch only **B1**. Confirm the Browser visually occupies B1 without a Firefox title bar.
2. In B1, enter distinct **English/number** text in the address bar and Google input.
3. Switch to **Zhuyin**, compose and commit Chinese text, then switch back to English and continue typing.
4. Launch **B2-B4** and repeat English/number + Zhuyin in every Browser. Input must remain in the clicked native Firefox window.
5. Toggle **Show IDs** on/off and repeat input.
6. Toggle **Auto Fit / Free Layout**, resize/move panes, and verify Firefox follows the corresponding pane rectangle.
7. Move the whole Workspace Window. All pseudo-docked Firefox windows must track it without stealing focus.
8. Maximize/restore a Browser pane. Hidden sibling Browsers must not float above the maximized pane.
9. Minimize and restore the Workspace. Pseudo-docked Firefox windows must hide and return with it.
10. Close/reopen Browser panes and repeat English/number + Zhuyin.
11. If B1-B4 remain stable, add B5-B8 and repeat routing / IME checks.
12. If normal activation fails, use `⌖ Focus` once only as a recovery diagnostic and capture `logs\runtime\AIEngineeringWorkspace_*.log`.
13. Runtime evidence should show `SetParentUsed=False`, `NativeInputMode=TopLevelPseudoDock`, `PersistentInputBridgeAttached=False`, and no `AttachThreadInput` / root `SetFocus` recovery path.
