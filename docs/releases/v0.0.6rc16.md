# AI Engineering Workspace v0.0.6rc16

## Scope

Native Firefox activation ownership and active-Browser input-language synchronization. This continues the active v0.0.6 RC line and is not a frozen release.

## Real-machine finding from rc15

The rc15 run confirmed a broader pattern than maximize/restore alone:

- a dock transaction could report successful Firefox root focus, then WPF MainWindow could become foreground/focus again shortly afterward;
- opening more Browser panes increased the frequency of input loss;
- Show IDs (the large B#/F# endpoint-highlight mode), Auto Fit/layout changes, and other WPF-owned transitions could leave Firefox unable to accept both English/number and Zhuyin input;
- deleting Browser panes and launching fresh ones could temporarily restore typing because docking performed a new root-focus handoff;
- the Workspace and Firefox threads could temporarily report different HKLs after switching input language.

The resulting fault model is **native Browser activation ownership**, not a fixed Browser-count limit and not an IME-only defect.

## rc16 change

- Keep the one-shot `FirefoxInputCoordinator` focus transaction: temporary `AttachThreadInput`, `SetFocus` on the reparented Firefox root HWND, and detach in `finally`.
- Record one active docked Firefox root HWND centrally.
- Observe `WM_PARENTNOTIFY` mouse-down and `WM_MOUSEACTIVATE` on the WPF-owned `BrowserDockHost`; a real mouse interaction with Firefox marks that root active and immediately re-establishes the native focus transaction.
- Do not depend on WPF `PreviewMouseDown` to observe clicks that occur inside hosted Win32 Firefox content.
- Keep WPF Browser-chrome activation and native Browser activation on the same active-root model.
- Clear active-Browser ownership when the user activates a File pane so later Workspace layout recovery does not steal focus from File Manager.
- After Show IDs on/off, layout-mode toggle, Add Browser, Workspace viewport resize, and explicit Browser maximize/restore, defer recovery until layout/repaint settles and refocus only the active Browser.
- When WPF accepts `WM_INPUTLANGCHANGE`, compare Workspace-thread and Firefox-thread HKL values and post `WM_INPUTLANGCHANGEREQUEST` only to the active Firefox root if they differ.
- Do not call `ActivateKeyboardLayout`, synthesize `WM_IME_COMPOSITION`, or enumerate/rank guessed Firefox compositor/content child HWNDs.

## Windows manual PASS gate

Without pressing the `⌖` Focus button:

1. Launch B1-B4 and verify English/number input in B1 -> B2 -> B3 -> B4 -> B1.
2. Switch to Zhuyin and verify composition/commit in B1 -> B3 -> B2, then switch back to English/number and continue typing.
3. Add B5-B8. Verify B1 and B3 still accept input after all eight Browser panes exist; then verify B5 -> B8 -> B2 cross-pane switching.
4. With B3 active, toggle **Show IDs** on and off. B3 must continue accepting English/number and Zhuyin. Click B1/B2 afterward and both must accept input without Focus.
5. Close several Browser panes, including the currently active one, then add/reopen Browser panes. Existing and newly docked Browsers must accept input without deleting every Browser first.
6. Maximize and restore B1 and B3 with Show IDs both off and on. English/number and Zhuyin must remain usable.
7. Activate a File pane, use its controls, then click a Browser. File-pane focus must not be stolen by background Browser recovery, and the subsequent native Browser click must restore Firefox input.
8. If any step fails, capture `logs\runtime\AIEngineeringWorkspace_*.log`. Look for `Native Firefox activation observed`, `Active Firefox root changed`, transactional handoff fields, active Browser HWND, WPF/Firefox HKLs, and `Firefox input-language request posted`.
