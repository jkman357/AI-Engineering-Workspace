# AI Engineering Workspace v0.0.6rc14

## Scope

Firefox IME / Input-Language Diagnostics. This continues the active v0.0.6 RC line and is not a frozen release.

Real-machine rc13 testing refined the failure boundary: ordinary English/number key input can work across B1-B4, while switching the active input method to Zhuyin can leave Firefox unable to perform IME composition. The tested Firefox windows also shared one Firefox PID/input thread, so rc14 gathers thread-level evidence rather than adding another speculative focus workaround.

## Changes

- Keep the rc13 centralized, one-shot `AttachThreadInput -> SetFocus(root HWND) -> immediate detach` focus handoff.
- Add `GetKeyboardLayout` evidence for both the Workspace UI thread and the Firefox window thread.
- Add `GetGUIThreadInfo` evidence for Firefox `hwndActive`, `hwndFocus`, and `hwndCaret` state.
- Probe each docked Browser from the existing one-second health loop, but write a runtime-log entry only when observable input state changes.
- Observe `WM_INPUTLANGCHANGEREQUEST`, `WM_INPUTLANGCHANGE`, `WM_IME_SETCONTEXT`, `WM_IME_STARTCOMPOSITION`, `WM_IME_COMPOSITION`, and `WM_IME_ENDCOMPOSITION` on the WPF MainWindow and WPF-owned Browser host HWND.
- Do not synthesize IME composition messages and do not call `ActivateKeyboardLayout` / forced layout synchronization in this RC.

## Windows manual validation gate

1. Launch and dock B1-B4.
2. Confirm ordinary English/number typing in Firefox address bar and page text fields.
3. With one docked Browser actively accepting input, switch **English/number -> Zhuyin** using the same normal Windows input-method action that reproduces the issue.
4. Attempt Zhuyin composition in the Firefox address bar and a page text field.
5. Switch **Zhuyin -> English/number** and confirm ordinary typing behavior again.
6. Repeat the language switch on at least one other Browser pane.
7. Save `logs/runtime/AIEngineeringWorkspace_*.log` immediately after reproduction.

The key rc14 log lines are:

```text
Firefox input-state transition observed...
WorkspaceHKL=...
BrowserHKL=...
InputLanguageMismatch=...
GuiActive=...
GuiFocus=...
GuiCaret=...
Input-language/IME message observed...
```

Interpretation for the next RC:

- **Firefox HKL does not change to the intended input language:** investigate input-language request propagation/synchronization.
- **Firefox HKL changes but Zhuyin still cannot compose:** investigate IME/TSF context activation across the reparented cross-thread HWND boundary rather than adding more `SetFocus` calls.
