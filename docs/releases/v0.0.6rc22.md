# v0.0.6rc22 — Firefox Input-Language Rollback Baseline

## Purpose

rc22 stops extending the rc16-rc21 Firefox input experiments and returns the active Browser input architecture to the rc15-era baseline that preceded active Firefox input-language synchronization.

Real-machine investigation established an important chronology:

- rc14/rc15 had successful English/number and Zhuyin input during the earlier multi-Browser tests;
- rc16 introduced native Browser activation-driven root focus recovery and corrective `WM_INPUTLANGCHANGEREQUEST` posting when Workspace/Firefox HKLs differed;
- rc17 retained that input-language synchronization and added a persistent per-Firefox-thread input bridge;
- rc18 removed the corrective synchronization, but the same long-lived Firefox process continued through later experiments;
- rc19-rc21 progressively removed `SetParent`, owner/style mutation, geometry mutation, and finally all Workspace Firefox window manipulation, yet the already-running Firefox process still could not switch Microsoft Zhuyin from English/direct-input mode to Chinese composition;
- Notepad++ on the same Windows session could switch English/Chinese with Shift and enter Chinese normally.

This supports a **process-state carry-over hypothesis**, not a proven root cause: an earlier RC may have altered Firefox input/IME state in a way that persisted for the lifetime of the Firefox process. rc22 therefore restores the last pre-rc16 input design and requires the first validation to start from a fresh Firefox process.

## Active rc22 Browser input policy

- Keep the rc15 `SetParent` Browser docking architecture.
- Keep Firefox child-HWND focus guessing removed.
- Keep `FirefoxInputCoordinator` as the only cross-thread root-focus recovery authority.
- Keep one-shot recovery only: temporary `AttachThreadInput`, `SetFocus` on the Firefox root HWND, immediate detach in `finally`.
- Keep HKL, foreground, `GetGUIThreadInfo`, and IME/input-language messages read-only diagnostics.
- **Do not post `WM_INPUTLANGCHANGEREQUEST` into Firefox.**
- **Do not call `ActivateKeyboardLayout` for Firefox.**
- **Do not synthesize `WM_IME_COMPOSITION` or related composition data.**
- **Do not install rc16 native-click `WM_PARENTNOTIFY` / `WM_MOUSEACTIVATE` automatic root-focus recovery.**
- **Do not restore rc17 persistent input-queue bridging.**

## Relationship to rc16-rc21

The source tree retains `docs/releases/v0.0.6rc16.md` through `v0.0.6rc21.md` as investigation history. Their experimental Browser hosting/input designs are not the active rc22 implementation.

## Fresh-process validation prerequisite

The first rc22 IME validation should be performed only when convenient and only after the existing Firefox work can be safely closed.

1. Close AI Engineering Workspace.
2. Close all Firefox windows when current work permits.
3. Confirm no `firefox.exe` process remains.
4. Start rc22.
5. Launch only B1 first.
6. Click a normal editable field (Google search is sufficient).
7. Type `abc123`.
8. Switch Microsoft Zhuyin from English to Chinese mode with Shift.
9. Compose and commit `你好`.
10. Switch back to English and type `xyz789`.

Do not use the `Focus` recovery button during this first gate.

### Interpretation

- **Fresh Firefox + rc22 Chinese PASS:** strongly supports process-state carry-over and makes rc15-era input behavior the preferred active baseline. Expand next to B1-B4, then Show IDs/maximize/restore.
- **Fresh Firefox + rc22 Chinese FAIL:** the rc15-era path itself is not sufficient on a clean process; capture the rc22 runtime log before changing Browser architecture again.

## Secondary multi-Browser gate after B1 passes

```text
B1: English/number -> Zhuyin -> English
B2: English/number -> Zhuyin
B3: English/number -> Zhuyin
B4: English/number -> Zhuyin
B1 -> B3 -> B2 -> B4 -> B1 repeated switching
Show IDs on/off
maximize / restore
```

No normal operation should require the Focus button.
